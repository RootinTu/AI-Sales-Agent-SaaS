# 企业知识库 1.5.5 线上基线评测报告（Bank RAG Benchmark）

## 1. 评测环境与配置
- **目标环境**：`https://ai.likeasuka.icu`（真实线上 PostgreSQL `pgvector HNSW` + `GIN` + FastAPI `1.5.5`）
- **模型配置**：问答模型 `qwen4-max`｜向量模型 `qwen3.7-text-embedding-flash`（1024 维）
- **评测数据集**：[Bank RAG Benchmark](https://github.com/sjtu-suzhou-ai-zhiwei-tech/bank-rag-benchmark)（100 份中文企业规程 PDF，共 265 页 / 24.1 MB，450 道评测题）
- **底库入库实测**：100 份 PDF 以 `PRIVATE` 私有模式批量导入（2 并发），即时 `READY` 99/100（1 份网关超时后异步完成落库），共切分并向量化 **449 个切片**（100% 完成向量索引），总入库耗时 **237.3s**（单份均值 ~2.4s）
- **抽样规模**：分层抽样 **50 题**（`seed=42`，5 大问题类型各 10 题；覆盖直接回答 32 题、要求补充信息 12 题、拒绝并说明 3 题、拒绝回答 3 题），1 并发稳态请求，**0 接口报错**
- **数据与配额清理**：评测结束后已自动删除全部 **100 份**测试 PDF（核验线上知识库恢复为原本 2 份文档，0 残留），并将临时调高的团队预算（`1,000,000`）与成员配额（`400,000`）原样恢复
- **问答 Token 消耗**：50 题问答合计 `168,306 Token`（平均 `3,366 Token / 题`）

## 4. 关键问题诊断与根因定位（高优先级优化清单）

本次评测中 **忠实度达到 100%、引用级错误率低至 0.32%、版本更新准确率达 95%**，说明 `1.5.5` 的提示词防噪、实引裁剪与 `qwen4-max` 生成质量非常过硬。失分的 12 道题（2 道 0 分 + 10 道 0.5 分）几乎全部集中在**检索召回与上下文组装阶段**，具体定位出 5 个可直接落地的改进点：

1. **【P0】同文档“首页抢槽、参数页漏召回”（直接导致 2 道 0 分 + 4 道 0.5 分）**
   - 典型案例：`BF-015`（命中 A07 第 1 页和材料页，漏掉第 2 页限额/期限条款，0 分）、`LR-001`（命中 A02 第 1 页，漏掉第 2 页 T+3 条款，0 分）、`MH-043` / `SIM-027`（漏 A17 第 2 页“最长 1 年”）、`VER-039`（漏 A12 第 2 页限额）、`SIM-014`（漏 A11 第 2 页限额）。
   - **根因**：规程类 PDF 第 1 页集中出现大标题、制度编号、适用范围，与问题向量相似度最高；进入 Top-K 后没有做邻近切片补全，导致具体数字所在的第 2 页被挤出。
   - **优化建议**：对命中得分靠前的文档引入 **邻近切片扩展（Sibling/Window Expansion）** 或 **按文档去重后取主片段 + 关键参数页**，同时适当把 `top_k` 从 4~5 放宽到 6~8（或按文档维度最多取 2 个互补切片）。
2. **【P0】已废止版本 / 征求意见稿在检索期未降权，挤占现行主规程名额**
   - 典型案例：`BF-008`（问是否可系统自动终审，征求意见稿 `A06` 与废止版 `A05` 抢占前排把现行 `A02` 挤出 Top 5）、`LR-054`（已废止 `A39` 占 3 槽挤掉现行 `A37` 与 `A38`）。
   - **优化建议**：支持文档级状态/时效元数据权重（或在重排阶段对标题/正文标记“已废止 / 征求意见稿 / 旧版 / 草稿”的片段施加适度降权系数，除非问题显式询问历史日期或旧版）。
3. **【P1】单文档多切片占坑挤压多跳检索文档召回（Multi-hop Full-Hit 仅 20%）**
   - 典型案例：`MH-036`、`MH-045`、`MH-026`、`SIM-026` 等需要同时汇总 3～5 份制度文档的题目，单一文档常占据 2～3 个槽位，导致其他关联文档无法进入上下文。
   - **优化建议**：在 `rank_candidates` 中加入 **MMR / 单文档槽位上限（例如 Top-6 内单文档最多占 2 槽）**，显著提升多文档 Full-Hit 召回率。
4. **【P1】`prune_uncited_sources` 在 0 引用拒答时未清空来源列表（明确 Bug）**
   - 典型案例：`LR-036` 模型明确回答“当前知识库中没有相关记载，无法确认”（0 处 `[资料 N]` 引用），但因为 `workflow.py` 中 `if not cited_order: return content, sources`，最终仍把 5 条无关候选文档返回给了前端。
   - **优化建议**：当 `not cited_order` 且回答命中拒答/无法确认表述时，应返回 `sources=[]`，避免界面出现“无相关资料但下方挂 5 个参考来源”的割裂体验。
5. **【P1】线上并发超时（Nginx 504）与分段延迟可观测性**
   - 实测在 3 并发下上传大 PDF 或 `qwen4-max` 长回答超过 60s 时，线上 Nginx 返回 `504 Gateway Time-out`（1 并发下 50 题 0 报错，但最大单题已达 `26.0s`）。
   - **优化建议**：线上 Nginx 针对 `/api/v1/knowledge/` 调大 `proxy_read_timeout` 至 `180s`；同时在 `KnowledgeService.ask()` 中把 `embedMs`、`vectorDbMs`、`lexicalDbMs` 写入 `model_call` 元数据，方便在线直接区分“纯检索延迟”与“LLM 生成延迟”。
